# Phase 7 — Summaries: on demand, focus-off, end of day + email outbox

**Status: built 2026-10-26** (automated tests pass). Hands-on checks: [VERIFY.md](../VERIFY.md).

Summaries are generated by our own LLM call (no longer by the IDE's model) and stored in the DB. Three triggers: A asks, focus mode turns off, and 23:59 every day. The 23:59 summary is "emailed": for now, that means written to `data/outbox/` as a ready-to-send email. A coworker adds real delivery later.

## Learn first
- **Structured output**: instead of asking the model for finished Markdown, we ask for JSON with fixed fields (`headline`, `highlights`, `by_space`, `action_items`). We get it with `llm.extract()`, a **forced tool call**: the model must "call" a `submit_summary` function, and the arguments are our JSON. Our template turns that JSON into the final text. The model decides *what* to say, and the template decides *how it looks*.
- **Scheduler (APScheduler)**: a timer inside the listener process that runs a function at 23:59. If the Mac is asleep at 23:59, the job is missed, so at startup we check whether yesterday's summary exists and create it if not.
- **Email outbox (mock)**: `shared/emailer.send(to, subject, html, text)` is the one function the rest of the code calls. The only backend for now writes two files:
  - `.html`, the email body you can open in a browser, and
  - `.eml`, a complete email (headers + HTML + plain text). Double-clicking it on macOS opens it in Apple Mail, looking exactly like the received email.

  Real sending (SMTP or Microsoft Graph) is later a new backend behind the same function. Nothing else changes.

- [ ] New table `summaries (id, kind, period_start, period_end, scope, data_json, markdown, created_at, delivered_at, delivered_to)`. `kind`: `on_demand` / `focus_session` / `end_of_day`. `delivered_to` holds the outbox path for now
- [ ] `shared/summary.py`:
  - [ ] `build_input(start, end, scope)`: messages grouped by space, oldest first, with counts and `data_starts_at`. Reuses the v1 `get_digest_input` logic; `held` = regular only, `all` = everything including `self`

  - [ ] Empty period → `summary/empty.md`, with no LLM call
  - [ ] More than ~300 messages → truncate (older gateway models have smaller context windows), and the template shows a note
- [ ] Tools (replacing the Phase 5 stubs): `summarize`, `list_summaries`, `get_summary`, `email_summary` (writes to the outbox and replies with the file path)

### Triggers
- [ ] On demand: chat ("summarize what I missed", "summarize Monday to Wednesday") and `/summary`
- [ ] Focus off: `focus.turn_off()` → `generate(session.start, now, "held", "focus_session")` → post `chat/focus_off_summary.md` in the Webex Assistant space. Runs in the background, so the "focus is off" reply is instant
- [ ] End of day: `listener/scheduler.py` (APScheduler cron at `EOD_TIME=23:59` local) → `generate(today, scope=EOD_SCOPE, kind="end_of_day")` → `emailer.send(...)` + post in the space
- [ ] Startup catch-up: if `kv.eod_last_date` < yesterday, generate the missing days (max 3)

### Email outbox (`shared/emailer.py`)
- [ ] `.env.example`: `EMAIL_BACKEND=outbox`, `EMAIL_TO` (defaults to A's Webex email), `EMAIL_FROM`, `OUTBOX_DIR=data/outbox`
- [ ] Subject from `summary/email_subject.txt`, HTML body from `summary/email_body.html` (summary Markdown → HTML, inline CSS so it looks right in mail apps), plain text from `summary/email_body.txt`
- [ ] Outbox backend: build the message with Python's `email.message.EmailMessage`, then write `data/outbox/<date>_<kind>_<id>.eml` and `.html`. Print one line: `[email] wrote data/outbox/…eml (to a@…)`
- [ ] Docstring at the top of `emailer.py` for the coworker: what `send()` receives, where to add `SmtpBackend` / `GraphBackend`, and the settings it would need
